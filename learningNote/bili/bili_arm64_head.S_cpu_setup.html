1. 概述与调用上下文

1.1 调用点

// primary_entry (head.S:119-130)
    mov     x0, x19                     // x0 = boot MMU flag
    bl      init_kernel_el              // → EL1, 关 MMU, w0=cpu_boot_mode
    mov     x20, x0                     // x20 = cpu_boot_mode

    bl      __cpu_setup              // ★ 配置 TCR/MAIR, 返回 SCTLR
    b       __primary_switch            // → 用 x0 的值开启 MMU
// ============ __cpu_setup 的输入/输出 ============ 进入时: 异常级别: EL1 MMU: OFF 栈: early_init_stack (4KB) 运行段: .idmap.text (identity mapping 保护下) 返回: x0 = INIT_SCTLR_EL1_MMU_ON ← 这是开启 MMU 的钥匙 包含 M=1, C=1, I=1 等所有需要的 bit 调用者不需要传任何参数; 配置完全由编译选项和硬件特性决定

1.2 代码段属性

.pushsection ".idmap.text", "a"    // ★ 关键: 放在 idmap 段

.pushsection 把 __cpu_setup 放到 .idmap.text 段。这意味着这段代码在 identity mapping 保护下执行——即使 MMU 页面表切换还在进行中，CPU 也能安全取指。它是 idmap 生命周期中的最后一环。

2. 第一阶段：TLB 清空 + 调试寄存器清空 (lines 466-473)

SYM_FUNC_START(__cpu_setup)
    tlbi    vmalle1                    // ① 全刷 EL1 TLB
    dsb     nsh

    msr     cpacr_el1, xzr             // ② 复位 CPACR_EL1
    mov     x1, MDSCR_EL1_TDCC         // ③ 准备 MDSCR_EL1 值
    msr     mdscr_el1, x1              //    写入 MDSCR_EL1
    reset_pmuserenr_el0 x1             // ④ 宏: 清 PMUSERENR_EL0
    reset_amuserenr_el0 x1             // ⑤ 宏: 清 AMUSERENR_EL0

① tlbi vmalle1 — 全刷 TLB

指令含义
TLBI VMALLE1使 EL1 控制的所有阶段 1 TLB entry 失效。参数: 所有 ASID, 所有 VA

旧页表（bootloader 留下的或 kexec 留下的）可能在 TLB 中还有缓存条目。新构建的 idmap 页表必须从内存中重新遍历，不能命中旧的 TLB 缓存。TLB 清空后必须跟 DSB NSH 确保操作全局可见。

② msr cpacr_el1, xzr — 复位 CPACR_EL1

CPACR_EL1 (Architectural Feature Access Control Register) 控制 EL0/EL1 对 SIMD/FP/SVE 等功能的访问。写 xzr (全 0) 意味着禁止 EL0 和 EL1 访问 SIMD/FP 寄存器。启动阶段不需要浮点或向量操作，后续 C 代码会重新启用。

③ msr mdscr_el1, MDSCR_EL1_TDCC — 配置调试通道

MDSCR_EL1 (Monitor Debug System Control Register)。MDSCR_EL1_TDCC 设置 trap 位，禁止 EL0 访问 Debug Communication Channel (DCC)。内核不需要用户态访问调试通道。

④⑤ reset_pmuserenr_el0 / reset_amuserenr_el0 — 禁止 EL0 性能监控

两个宏分别清零 PMUSERENR_EL0 (Performance Monitors User Enable) 和 AMUSERENR_EL0 (Activity Monitors User Enable)，禁止 EL0 访问 PMU 和 AMU 计数器。安全加固。

💡 六条指令三个目的： TLB 清空保证页表一致性、CPACR 禁止 SIMD 避免启动阶段误用、MDSCR+PMU+AMU 禁止 EL0 调试/性能访问是安全加固。它们和 MMU 配置无关，但必须在 MMU 开启前的"干净状态"中完成。

3. 第二阶段：MAIR_EL1 和 TCR_EL1 默认值 (lines 479-492)

    mair    .req    x17                // ⑥ 别名: mair → x17
    tcr     .req    x16                // ⑦ 别名: tcr  → x16
    tcr2    .req    x15                // ⑧ 别名: tcr2 → x15
    mov_q   mair, MAIR_EL1_SET         // ⑨ 加载 MAIR 默认值
    mov_q   tcr, TCR_T0SZ(IDMAP_VA_BITS) | TCR_T1SZ(VA_BITS_MIN) |
                 TCR_CACHE_FLAGS | TCR_SHARED | TCR_TG_FLAGS |
                 TCR_KASLR_FLAGS | TCR_ASID16 | TCR_TBI0 | TCR_A1 |
                 TCR_KASAN_SW_FLAGS | TCR_MTE_FLAGS
                                       // ⑩ 加载 TCR 默认值
    mov     tcr2, xzr                  // ⑪ TCR2_EL1 = 0
    tcr_clear_errata_bits tcr, x9, x5  // ⑫ 清除 CPU 勘误位

⑥⑦⑧ 寄存器别名

.req 是汇编器伪指令，给寄存器起别名。后面的代码用 mair 代替 x17、tcr 代替 x16，语义清晰。

⑨ mov_q mair, MAIR_EL1_SET — 内存属性表

MAIR_EL1 (Memory Attribute Indirection Register) 定义了页表中 AttrIndx 字段 (bits[4:2]) 对应的实际内存类型。它有 8 个槽 (Attr0~Attr7)，每个 8 bits：

槽值内存类型对应页表 AttrIndx
Attr00x00Device-nGnRnE (严格设备内存)0
Attr10x04Device-nGnRE (设备内存)1
Attr20x44Normal Non-Cacheable2
Attr30xffNormal WBWA (回写+写分配)3 ← 内核代码/数据用

页表中的 AttrIndx=3 (0b011) 查 MAIR_EL1 的 Attr3 = 0xff = Inner WBWA + Outer WBWA。

⑩ mov_q tcr, TCR_... — 翻译控制寄存器

TCR_EL1 (Translation Control Register) 控制 MMU 的翻译行为。mov_q 是批量加载立即数的宏（2~4 条 movz/movk 指令）。逐位分解：

字段表达式计算含义
T0SZTCR_T0SZ(IDMAP_VA_BITS)64-48 = 16TTBR0 翻译区域 = 48 bits
★ idmap 的 VA 空间在此!
T1SZTCR_T1SZ(VA_BITS_MIN)64-48 = 16TTBR1 翻译区域 = 48 bits
★ 内核主体 VA 空间 (0xffff...)
TG0/TG1TCR_TG_FLAGSTCR_TG0_4K | TCR_TG1_4K双 TTBR 都用 4KB 粒度
SH0/SH1TCR_SHAREDInner Shareable页表遍历的缓存共享域
IRGN0/IRGN1TCR_CACHE_FLAGSWBWA页表遍历的缓存策略
ASTCR_ASID1616-bit ASID支持 65536 个地址空间 ID
TBI0TCR_TBI0Top Byte IgnoredTTBR0 翻译时忽略 VA 高 8 bits
A1TCR_A1ASID 定义来自 TTBR1内核用 TTBR1 管理 ASID

T0SZ 为什么至关重要

// ============ T0SZ=16 决定了 idmap 的 VA 范围 ============ TCR_EL1.T0SZ = 16 → TTBR0 的地址区域大小 = 64 - 16 = 48 bits → 只有 VA[47:0] 被用作翻译输入 idmap 创建的页表: VA[47:0] → PA[47:0], VA==PA TCR_EL1.T0SZ=48 → 硬件只取 VA[47:0] 做翻译 ★ 两者必须匹配! 如果 T0SZ=52 但 idmap 用 48-bit, 硬件会用错误 的 VA 位去查页表, 结果不可预测

⑪ mov tcr2, xzr — TCR2_EL1 初始清零

TCR2_EL1 是 ARMv8.4+ 的扩展寄存器，保存 TCR_EL1 放不下的额外翻译控制位。默认全 0。

⑫ tcr_clear_errata_bits tcr, x9, x5 — CPU 勘误清除

某些 CPU 的 TCR_EL1 特定 bit 有硬件 bug，需要软件规避。这个宏展开为针对已知勘误位的位清除操作。对于没有勘误的 CPU（如 cortex-a57），宏展开为空。

4. 第三阶段：逐特性调整 (lines 490-541)

4.1 52-bit VA 扩展 (lines 490-498)

#ifdef CONFIG_ARM64_VA_BITS_52
    mov     x9, #64 - VA_BITS          // ⑬ 计算 52-bit 的 T1SZ
alternative_if ARM64_HAS_VA52
    tcr_set_t1sz    tcr, x9            // ⑭ 调整 T1SZ = 12 (64-52)
#ifdef CONFIG_ARM64_LPA2
    orr     tcr, tcr, #TCR_DS         // ⑮ LPA2 额外设置
#endif
alternative_else_nop_endif
#endif
行指令含义
⑬mov x9, #64-52 = 1252-bit VA 要缩小 T1SZ → TTBR1 区域扩展到 52 bits
⑭tcr_set_t1sz tcr, x9宏: bfi — 把 x9 的值嵌入 TCR 的 T1SZ 位域。只有当硬件真的支持 52-bit VA 时才执行 (alternative_if)
⑮orr tcr, tcr, #TCR_DSLPA2 (Large Physical Address) 需要设置 TCR_DS 位, 启用 52-bit 输出地址
💡 注意 T0SZ 没有变。 即使内核主体用 52-bit VA, idmap 依然只用 48-bit —— T0SZ 保持 16, TTBR0 区域还是 48 bits。和IDMAP_VA_BITS=48 保持一致。

4.2 物理地址大小检测 (lines 500-503)

    tcr_compute_pa_size tcr, #TCR_IPS_SHIFT, x5, x6
                                       // ⑯ 设置 TCR_EL1.IPS

⑯ 宏展开为读取 ID_AA64MMFR0_EL1.PARange，把硬件支持的最大物理地址位数 (32/36/40/44/48/52) 写入 TCR_EL1 的 IPS 位域。你当前配置的 52-bit PA 对应 IPS=0b110。

4.3 硬件 Access Flag 更新 (lines 504-520)

#ifdef CONFIG_ARM64_HW_AFDBM
    mrs     x9, ID_AA64MMFR1_EL1      // ⑰ 读硬件特性寄存器
    ubfx    x9, x9, ID_AA64MMFR1_EL1_HAFDBS_SHIFT, #4
                                       // ⑱ 提取 HAFDBS 位域
    cbz     x9, 1f                     // ⑲ 硬件不支持 → 跳过
    orr     tcr, tcr, #TCR_HA          // ⑳ 启用硬件 AF 自动更新
#ifdef CONFIG_ARM64_HAFT
    cmp     x9, ID_AA64MMFR1_EL1_HAFDBS_HAFT
    b.lt    1f
    orr     tcr2, tcr2, TCR2_EL1_HAFT  // ㉑ HAFT 扩展支持
#endif
1:
#endif
行指令含义
⑰mrs x9, ID_AA64MMFR1_EL1读取 AArch64 内存模型特性寄存器 1
⑱ubfx ...HAFDBS_SHIFT, #4提取 bits[HAFDBS_SHIFT:+4] — 硬件 AF/DBM 支持级别
0 = 不支持, 1 = AF only, 2 = AF+DBM, 3 = AF+DBM+HAFT
⑲cbz x9, 1f不支持 → 跳过整个 AF 设置块
⑳orr tcr, tcr, #TCR_HA设置 TCR_EL1.HA bit = 1
★ 此后 CPU 首次访问一个页时, 自动将 PTE 的 AF(bit10) 置 1
★ 不再需要软件手动判断 + 写回
㉑orr tcr2, tcr2, TCR2_EL1_HAFTHAFT = Hardware Access Flag for Table descriptors — 连页表本身的 AF 也由硬件管理

AF 自动更新的实际影响

没有 HA 时 (软件管理 AF)：

  1. CPU 访问一个 PTE 的 AF=0 的页面
  2. 触发 Access Flag fault (数据异常)
  3. 内核 fault handler 捕获 → 手动将 AF 置 1 → 写回 PTE → 返回
  4. 每条 PTE 首次访问都有这个开销

有 HA 时 (硬件管理 AF)：

  1. CPU 访问一个 PTE 的 AF=0 的页面
  2. 硬件自动将 AF 置 1 → 翻译继续 → 完成
  3. 零软件开销

4.4 写入 MAIR_EL1 和 TCR_EL1 (lines 521-522)

    msr     mair_el1, mair             // ㉒ 写入 MAIR_EL1
    msr     tcr_el1, tcr               // ㉓ 写入 TCR_EL1

经过上面所有逐特性调整后的 mair 和 tcr 值最终写入硬件寄存器。此后 MMU 一旦开启，新的 MAIR/TCR 立刻生效。

4.5 PIE: 权限间接扩展 (lines 524-535)

    mrs_s   x1, SYS_ID_AA64MMFR3_EL1  // ㉔ 读 ID_AA64MMFR3_EL1
    ubfx    x1, x1, #ID_AA64MMFR3_EL1_S1PIE_SHIFT, #4
                                       // ㉕ 提取 S1PIE 位域
    cbz     x1, .Lskip_indirection     // ㉖ 不支持 → 跳过

    mov_q   x0, PIE_E0_ASM
    msr     REG_PIRE0_EL1, x0          // ㉗ 写 PIRE0_EL1
    mov_q   x0, PIE_E1_ASM
    msr     REG_PIR_EL1, x0            // ㉘ 写 PIR_EL1
    orr     tcr2, tcr2, TCR2_EL1_PIE   // ㉙ TCR2_EL1.PIE=1

.Lskip_indirection:

ARMv8.4+ 引入的 PIE 允许用 4 位 PTE 权限索引 (bits[58:55]) 查 16-entry 权限表（PIRE0_EL1/PIR_EL1），每个 entry 定义更丰富的权限组合。如果硬件不支持，整段跳过。

4.6 TCR2_EL1 写入 (lines 537-541)

    mrs_s   x1, SYS_ID_AA64MMFR3_EL1
    ubfx    x1, x1, #ID_AA64MMFR3_EL1_TCRX_SHIFT, #4
                                       // ㉚ 检测是否支持 TCR2
    cbz     x1, 1f                     // ㉛ 不支持 → 跳过
    msr     REG_TCR2_EL1, tcr2         // ㉜ 写入 TCR2_EL1
1:

TCR2_EL1 寄存器本身是 ARMv8.4+ 新增的。如果硬件没有 TCR2，写入它会 UNDEFINED。所以先通过 ID_AA64MMFR3_EL1.TCRX 检查是否存在。

5. 返回值：INIT_SCTLR_EL1_MMU_ON (lines 543-552)

    mov_q   x0, INIT_SCTLR_EL1_MMU_ON // ㉝ 加载 SCTLR MMU-ON 配置
    ret                                // ㉞ 返回 primary_entry

    .unreq  mair                       // 清除别名 (汇编规范)
    .unreq  tcr
    .unreq  tcr2
SYM_FUNC_END(__cpu_setup)

㉝ mov_q x0, INIT_SCTLR_EL1_MMU_ON

和 init_kernel_el 中的 INIT_SCTLR_EL1_MMU_OFF 是对称的一对。两者的关键差异：

INIT_SCTLR_EL1_MMU_OFF (关)

M=0MMU OFF
C=0D-cache OFF
I=0I-cache OFF
+5 个扩展位LSMAOE, nTLSMD 等

值: 0x30500800 (LE)

INIT_SCTLR_EL1_MMU_ON (开)

M=1MMU ON ★
C=1D-cache ON ★
I=1I-cache ON ★
SA=1SP 对齐检查
+ 更多扩展位WXN, IESB, EIS, 等

值: 多位置 1，与 OFF 互补

㉞ ret — 返回值交付 __primary_switch

关键：__cpu_setup 自己不写 SCTLR_EL1——它把配置好的 MMU_ON 值放在 x0 返回，由调用链的下一环 __primary_switch 在页表切换完成后写入。这样 SCTLR 的 M 位置 1 可以和新页表的 TTBR 切换精确同步，不会出现"MMU 开了但页表还没准备好"的瞬态。

完整调用链示意

// ============ MMU 开启的关键三步 ============ __cpu_setup() → x0 = INIT_SCTLR_EL1_MMU_ON (第1步: 准备钥匙) │ __primary_switch() → 切换 TTBR0_EL1/ TTBR1_EL1 (第2步: 切换页表) │ 写 SCTLR_EL1 = x0 (第3步: 用钥匙开启 MMU!) │ ISB ( 同步) ▼ MMU ON! → 第一条经 MMU 翻译的指令在此执行
