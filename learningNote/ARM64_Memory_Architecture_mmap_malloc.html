3.2 ARM64 架构特定处理

ARM64 在 arch/arm64/include/asm/mman.h 中实现了两个关键钩子：

ARCH arch_calc_vm_prot_bits()

将用户空间的 prot 标志转换为 VMA 标志：

  • PROT_BTI → VM_ARM64_BTI — Branch Target Identification
  • PROT_MTE → VM_MTE — Memory Tagging Extension
  • pkey bits → VM_PKEY_BIT[0-2] — Permission Overlay Extension

ARCH arch_calc_vm_flag_bits()

设置架构特定的默认 VMA 标志：

  • 匿名映射 + MTE 支持 → VM_MTE_ALLOWED
  • shmem/hugetlb 文件 + MTE 支持 → VM_MTE_ALLOWED
  • VM_DATA_DEFAULT_FLAGS 默认包含 VM_MTE_ALLOWED

🔄 7. TLB 与 ASID 管理

7.1 ASID (Address Space Identifier)

实现在 arch/arm64/mm/context.c：

  • 支持 8-bit 或 16-bit ASID（由 ID_AA64MMFR0_EL1 决定）
  • ASID 在进程切换时分配，用于避免全局 TLB 刷新
  • ASID_FIRST_VERSION = 1 << 16 — 版本号机制，溢出时全局刷新
  • KPTI 场景下 ASID 成对分配：偶数用于内核，奇数用于用户
  • MAX_PINNED_ASIDS — 预留的固定 ASID 数量

7.3 ARM64 TLB 关键特性

🏷️ Contiguous PTE (CONT_PTE)

连续 PTE 条目的 TLB 优化。16 个对齐的连续 PTE 可共享一个 TLB 条目。

定义在 pgtable-hwdef.h：CONT_PTE_SHIFT = PAGE_SHIFT + 4

分裂操作：split_contpte() (mmu.c:531)

🔄 Break-Before-Make

ARM 架构要求修改页表映射时必须先 invalidate 再建立新映射。

pgattr_change_is_safe() (mmu.c:126) 判断是否可以安全地原地修改 PTE 属性。

允许的安全修改：PTE_PXN | PTE_RDONLY | PTE_WRITE | PTE_NG 等权限位变化。

9.4 ARM64 关键实现要点

🔐 安全特性

  • KPTI — 内核页表隔离，ASID 成对分配
  • PAN — 内核访问用户地址需特权检查
  • BTI — 分支目标识别，防止 JOP 攻击
  • MTE — 内存标签扩展，检测 UAF/缓冲区溢出
  • POE — 权限覆盖扩展，细粒度页权限控制
  • GCS — 守护控制栈，防止返回地址篡改

⚡ 性能优化

  • Per-VMA Lock — RCU 保护的 VMA 锁，减少 mmap_lock 竞争
  • Contiguous PTE — 16个连续PTE合并为单TLB条目
  • Lazy MMU Mode — 批量页表修改延迟 TLB 刷新
  • Block Mapping — 使用 PMD/PUD 级别的巨大页映射
  • ASID — 避免进程切换时全 TLB 刷新
  • THP — 透明大页支持 (PMD/PUD级别)

📊 页表层级 (4KB 粒度)

  • PGD (Level 0) — 512 entries × 512GB = 256TB
  • PUD (Level 1) — 512 entries × 1GB = 512GB
  • PMD (Level 2) — 512 entries × 2MB = 1GB
  • PTE (Level 3) — 512 entries × 4KB = 2MB
  • TTBR0_EL1 → 用户空间 | TTBR1_EL1 → 内核空间

🎤 11. 面试高频考点 — mmap & malloc 深度问答

Q1: mmap 和 malloc 的本质区别是什么？底层分别走什么路径？

malloc (glibc)：用户态堆分配。小块内存（<128KB）从 brk() 堆扩展，大块内存（>128KB）内部调用 mmap(MAP_ANONYMOUS)。

  • brk 路径：sys_brk → do_brk_flags → 扩展堆 VMA，不立即分配物理页（demand paging）
  • mmap 路径：sys_mmap_pgoff → do_mmap → mmap_region → 创建 VMA，同样延迟分配

mmap (系统调用)：直接创建 VMA 映射，可以是匿名映射或文件映射。内核路径：SYSCALL_DEFINE6(mmap_pgoff) → ksys_mmap_pgoff → vm_mmap_pgoff → do_mmap → mmap_region → __mmap_new_vma。

关键差异：malloc 是 libc 函数，管理已映射内存；mmap 是系统调用，向内核申请新映射。malloc 可能复用已 free 的内存，mmap 总是创建新 VMA。

Q2: ARM64 下 mmap 返回的虚拟地址为何总是页对齐？页大小有哪些可能？

ARM64 支持 3 种页粒度，由 TCR_EL1.TG0/TG1 配置：

粒度页大小虚拟地址位页表层级
4KB4KB48-bit (256TB)PGD→PUD→PMD→PTE (4级)
16KB16KB47-bitPGD→PUD→PMD→PTE (4级，但编码不同)
64KB64KB52-bitPGD→PMD→PTE (3级，-1级抵消)

do_mmap 中 len = PAGE_ALIGN(len) 强制对齐，__get_unmapped_area 返回的地址也是页对齐的。面试常问：为什么必须页对齐？——因为 MMU 以页为单位进行地址翻译，非对齐地址无法建立 PTE 映射。

Q4: MAP_POPULATE 标志有什么作用？为何能减少缺页异常？

MAP_POPULATE 在 do_mmap() 末尾触发预映射（line 555-558）：

if (!IS_ERR_VALUE(addr) &&
    ((vm_flags & VM_LOCKED) ||
     (flags & (MAP_POPULATE | MAP_NONBLOCK)) == MAP_POPULATE))
    *populate = len;

调用者 vm_mmap_pgoff 随后执行 mm_populate(addr, len)，内部调用 __mm_populate → populate_vma_page_range，在返回用户态前预先触发缺页处理，将物理页映射好。

  • ✅ 优点：后续访问零缺页延迟，适合实时/低延迟场景
  • ❌ 缺点：增加 mmap 调用延迟，可能分配了不用的页（浪费内存）
  • ⚠️ 注意：MAP_LOCKED 隐含 MAP_POPULATE 语义（因为 mlock 需要页在场）

调用接口glibc malloc/freekmalloc(size, GFP_KERNEL)

ARM64 特色：kmalloc 返回的地址在 PAGE_OFFSET（0xffff_8000_0000_0000 附近），这是内核线性映射区，使用 TTBR1_EL1 页表，页表项在 paging_init() 时预建，无需缺页处理。

Q6: ARM64 下 mmap 一个文件时，内核如何建立文件页缓存与用户 VMA 的关联？

核心数据结构链路：

VMA (vm_area_struct)
  ├─ vm_file → struct file
  │              └─ f_mapping → struct address_space (文件页缓存)
  │                                ├─ i_pages (xarray: page->index → struct page)
  │                                └─ a_ops (address_space_operations)
  │                                     ├─ read_folio / writepage 等
  └─ vm_ops → struct vm_operations_struct
               └─ fault → filemap_fault  (缺页时调用)

流程：mmap(file, ...) → do_mmap 时记录 vma->vm_file = file，VMA 设置 vma->vm_ops = &filemap_vm_ops（通过 file->f_op->mmap 回调设置）。

缺页时：do_fault → do_read_fault → __do_fault → vma->vm_ops->fault = filemap_fault → 在 address_space->i_pages 中查找/读取 page → set_pte_at 建立映射。

Q7: mmap 的 MAP_SHARED vs MAP_PRIVATE 在内核中实现有何不同？fork 时如何体现？

特性MAP_SHAREDMAP_PRIVATE
VMA 标志VM_SHARED | VM_MAYSHARE无 VM_SHARED

COW 实现要点（ARM64）：fork 时 copy_page_range → copy_present_pte → PTE 设为只读（ptep_set_wrprotect），两个进程共享同一物理页。写入时触发 do_wp_page → wp_page_copy → 分配新物理页、复制内容、更新各自 PTE。

Q8: ARM64 VA_BITS 48 vs 52 对 mmap 可用空间有什么影响？

ARM64 地址空间分用户/内核两部分（各占一半）：

配置总 VA 空间用户空间内核空间TASK_SIZE
VA_BITS=48 (4KB)256TB128TB128TB0x0000_7fff_ffff_ffff
VA_BITS=48 (64KB)256TB128TB128TB0x0000_7fff_ffff_ffff
VA_BITS=52 (64KB)4PB2PB2PB0x0007_ffff_ffff_ffff

面试追问：52-bit 如何兼容 48-bit？ARMv8.2-LVA 通过 -1 级页表（由 TCR_EL1.DS 控制）额外增加一级。硬件遍历时根据 VA[51:48] 决定从 L-1 还是 L0 开始。内核中 pgtable_l4_enabled() 检查是否启用。

Q9: 内存碎片化对 mmap 大页映射有什么影响？内核如何应对？

问题：mmap 需要 2MB/1GB 大页时，需要连续物理页。碎片化导致分配失败，退化为 4KB 小页。

ARM64 透明大页 (THP)：CONFIG_TRANSPARENT_HUGEPAGE=y 时，缺页处理中 __handle_mm_fault 尝试 do_huge_pmd_anonymous_page，直接分配 PMD-mapped 2MB 页。如果分配失败，fallback 到 handle_pte_fault 用 4KB。

反碎片机制：

  • Buddy 迁移类型：UNMOVABLE / RECLAIMABLE / MOVABLE 分区，减少不可移动页阻挡
  • 内存规整 (compaction)：compact_zone 迁移 MOVABLE 页腾出连续区域
  • Pageblock 顺序：pageblock_order（通常 9，即 2MB），按迁移类型分组管理

Q10: mmap 的 MAP_FIXED vs MAP_FIXED_NOREPLACE 有何区别？

  • MAP_FIXED：强制使用指定地址，如果已有映射则先 munmap 再映射。危险——可能意外覆盖已有映射（如 ld.so、vDSO）。
  • MAP_FIXED_NOREPLACE：指定地址如果已被占用，返回 -EEXIST 而不是覆盖。安全替代方案。

内核实现（do_mmap line ~500）：

if (flags & MAP_FIXED_NOREPLACE) {
    if (find_vma_intersection(mm, addr, addr + len))
        return -EEXIST;
}

典型面试场景：glibc 加载器使用 MAP_FIXED_NOREPLACE 防止覆盖已加载库；JVM/Go runtime 使用 MAP_FIXED 管理自定义堆。

Q11: mmap(MAP_ANONYMOUS) 后的内存在 fork() 时如何共享？COW 如何触发？

fork 时：dup_mmap → copy_page_range（遍历所有 VMA）→ copy_pte_range：

// mm/memory.c
copy_present_pte() {
    // 如果是可写 PTE，设为只读（触发 COW）
    if (pte_write(pte))
        pte = pte_wrprotect(pte);  // ARM64: 清除 PTE_DBM 中的写权限
    // 增加 page->_refcount（记录共享计数）
    set_pte_at(dst_mm, addr, dst_pte, pte);
}

写入时：MMU 触发 permission fault（ESR_EL1.ISS = 0b0011xx），进入 do_page_fault → handle_mm_fault → do_wp_page → wp_page_copy → 分配新物理页、复制内容、设置可写 PTE。

ARM64 专用：PTE 的 DBM (Dirty Bit Modifier) 位决定硬件写入行为。读写权限由 PTE[6:4]（AP[2:0]）控制：AP=0b011 表示 EL0/EL1 可读写。

实验 1: 验证 mmap MAP_POPULATE 与缺页延迟差异

目的：对比普通 mmap 与 MAP_POPULATE mmap 的首次访问延迟，验证预映射效果。

// test_mmap_populate.c
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/mman.h>
#include <time.h>
#include <unistd.h>

#define MAP_SIZE (256 * 1024 * 1024UL)  // 256MB
#define PAGE_COUNT (MAP_SIZE / 4096)

static unsigned long long nstime(void) {
    struct timespec ts;
    clock_gettime(CLOCK_MONOTONIC, &ts);
    return ts.tv_sec * 1000000000ULL + ts.tv_nsec;
}

int main(void) {
    unsigned long long t0, t1;
    volatile char *p;
    int i;

    // === 普通 mmap（不预映射）===
    t0 = nstime();
    char *m1 = mmap(NULL, MAP_SIZE, PROT_READ|PROT_WRITE,
                    MAP_ANONYMOUS|MAP_PRIVATE, -1, 0);
    t1 = nstime();
    printf("mmap (lazy) syscall: %llu us\n", (t1 - t0) / 1000);

    t0 = nstime();
    for (i = 0; i < PAGE_COUNT; i += 256)  // 每隔256页触发缺页
        m1[i * 4096] = 'A';
    t1 = nstime();
    printf("First touch (lazy) : %llu us\n", (t1 - t0) / 1000);
    munmap(m1, MAP_SIZE);

    // === MAP_POPULATE mmap（预映射）===
    t0 = nstime();
    char *m2 = mmap(NULL, MAP_SIZE, PROT_READ|PROT_WRITE,
                    MAP_ANONYMOUS|MAP_PRIVATE|MAP_POPULATE, -1, 0);
    t1 = nstime();
    printf("mmap (POPULATE) syscall: %llu us\n", (t1 - t0) / 1000);

    t0 = nstime();
    for (i = 0; i < PAGE_COUNT; i += 256)
        m2[i * 4096] = 'B';
    t1 = nstime();
    printf("First touch (POPULATE): %llu us\n", (t1 - t0) / 1000);
    munmap(m2, MAP_SIZE);

    return 0;
}

预期结果：MAP_POPULATE 的 mmap 调用时间远大于普通 mmap，但后续首次访问几乎为零（因为页已映射）。普通 mmap 首次触页时间远大于 POPULATE。

验证方式：同时 perf stat -e page-faults,minor-faults 运行，观察缺页计数差异。

    // 1. 匿名私有映射

                      MAP_ANONYMOUS|MAP_PRIVATE, -1, 0);
    printf("ANON_PRIVATE: %p\n", anon);

    // 2. 文件私有映射
    int fd = open("/bin/ls", O_RDONLY);
    char *file_priv = mmap(NULL, 4096, PROT_READ,
                           MAP_PRIVATE, fd, 0);
    printf("FILE_PRIVATE: %p\n", file_priv);

    // 3. 匿名共享映射
    char *shared = mmap(NULL, 4096, PROT_READ|PROT_WRITE,
                        MAP_ANONYMOUS|MAP_SHARED, -1, 0);
    printf("ANON_SHARED: %p\n", shared);

    printf("\n=== Press Enter to exit ===\n");
    getchar();

    // 在另一个终端: cat /proc/$(pidof test_mmap_view)/maps
    return 0;
}

实验 4: 验证 COW（写时复制）在 fork 后的行为

目的：通过 /proc/PID/smaps 观察 fork 前后和写入前后的 PSS/RSS 变化，验证 COW 机制。

// test_cow.c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/mman.h>
#include <sys/wait.h>
#include <unistd.h>

#define REGION_SIZE (10 * 1024 * 1024)  // 10MB

int main(void) {
    char *region = mmap(NULL, REGION_SIZE, PROT_READ|PROT_WRITE,
                        MAP_ANONYMOUS|MAP_PRIVATE, -1, 0);
    memset(region, 'X', REGION_SIZE);  // 触发所有页分配
    printf("=== Before fork (PID=%d) ===\n", getpid());
    printf("Region: %p - %p\n", region, region + REGION_SIZE);
    printf("Press Enter after checking /proc/%d/smaps...\n", getpid());
    getchar();

    pid_t pid = fork();
    if (pid == 0) {
        // 子进程：先读（不触发 COW），再写（触发 COW）
        printf("Child (PID=%d): reading first byte = %c\n",
               getpid(), region[0]);

        printf("Child: Press Enter before writing...\n");
        getchar();

        region[0] = 'C';  // ← 触发 COW！该页被复制
        region[REGION_SIZE/2] = 'C';  // 中间页也触发 COW
        printf("Child: Wrote to region. Press Enter...\n");
        getchar();
        exit(0);
    } else {
        // 父进程：先读，再写不同页
        printf("Parent: reading first byte = %c\n", region[0]);

        printf("Parent: Press Enter before writing...\n");
        getchar();

        region[4096] = 'P';  // 写第2页，触发独立的 COW
        printf("Parent: Wrote to page 2. Press Enter...\n");
        getchar();
        wait(NULL);
    }
    return 0;
}

验证步骤：在每个暂停点，在另一个终端执行：

# 查看映射的 Rss/Pss（共享计数）
cat /proc/PID/smaps | grep -A 20 "test_cow"

# 关键指标变化：
# fork 前: Rss=~10MB, Pss=~10MB (单进程)
# fork 后写前: Rss=~10MB, Pss=~5MB  (父子各5MB，共享物理页)
# 子进程写后: Rss不变, Pss增大      (COW页变为独占)
# 父进程写后: Rss稍增, Pss增大      (各自COW的页不再共享)

实验 5: 对比 malloc 小内存 (brk) vs 大内存 (mmap) 的分配策略

目的：验证 glibc 对不同大小 malloc 使用 brk 还是 mmap 的策略。

// test_malloc_strategy.c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <malloc.h>
#include <unistd.h>

void show_heap_info(const char *label) {
    struct mallinfo2 mi = mallinfo2();
    printf("[%s] arena=%zu, hblkhd=%zu, uordblks=%zu, fordblks=%zu\n",
           label, mi.arena, mi.hblkhd, mi.uordblks, mi.fordblks);
    // hblkhd > 0 表示使用了 mmap 分配
}

int main(void) {
    printf("MALLOC_MMAP_THRESHOLD = %ld\n",
           M_MMAP_THRESHOLD);  // 默认 128KB

    show_heap_info("start");

    // 小内存: 走 brk (堆)
    void *p1 = malloc(1024);
    void *p2 = malloc(4096);
    void *p3 = malloc(64 * 1024);  // 64KB < 128KB
    show_heap_info("small allocs (brk)");
    printf("p1=%p p2=%p p3=%p\n", p1, p2, p3);

    // 大内存: 走 mmap
    void *p4 = malloc(256 * 1024);  // 256KB > 128KB
    show_heap_info("large alloc (mmap)");
    printf("p4=%p (should be far from heap)\n", p4);

    // 查看 /proc/PID/maps 确认:
    // brk 分配: 在 [heap] 区域内
    // mmap 分配: 在独立的 mmap 匿名区域
    printf("\nPID=%d: cat /proc/%d/maps to verify\n", getpid(), getpid());
    getchar();

    free(p1); free(p2); free(p3); free(p4);
    return 0;
}

验证：cat /proc/PID/maps 观察：

  • [heap] 区域内的地址来自 brk 扩展
  • 远离 heap 的匿名映射区域（无 inode、无路径名）来自 mmap

实验 6: ARM64 页表遍历验证 — 使用 devmem 读取 PTE

目的：通过内核模块读取指定虚拟地址的 PTE 条目，验证 ARM64 四级页表结构。

// pte_walk.c (内核模块，在 QEMU 中通过 scp 上传后 insmod)
#include <linux/module.h>
#include <linux/mm.h>
#include <linux/sched.h>
#include <asm/pgtable.h>

static void dump_pte(unsigned long vaddr) {
    pgd_t *pgd;
    p4d_t *p4d;
    pud_t *pud;
    pmd_t *pmd;
    pte_t *pte;
    struct mm_struct *mm = current->mm;
    unsigned long pfn;

    pgd = pgd_offset(mm, vaddr);
    if (pgd_none(*pgd) || pgd_bad(*pgd)) {
        pr_info("PGD: empty/bad\n");
        return;
    }
    pr_info("PGD: %px val=0x%016llx\n", pgd, pgd_val(*pgd));

    p4d = p4d_offset(pgd, vaddr);
    pud = pud_offset(p4d, vaddr);
    if (pud_none(*pud) || pud_bad(*pud)) {
        pr_info("PUD: empty/bad\n");
        return;
    }
    pr_info("PUD: %px val=0x%016llx\n", pud, pud_val(*pud));

    pmd = pmd_offset(pud, vaddr);
    if (pmd_none(*pmd) || pmd_bad(*pmd)) {
        pr_info("PMD: empty/bad\n");
        return;
    }
    pr_info("PMD: %px val=0x%016llx\n", pmd, pmd_val(*pmd));

    pte = pte_offset_map(pmd, vaddr);
    if (pte_none(*pte)) {
        pr_info("PTE: empty (not mapped yet)\n");
        return;
    }
    pfn = pte_pfn(*pte);
    pr_info("PTE: %px val=0x%016llx pfn=%lu phys=0x%016llx\n",
            pte, pte_val(*pte), pfn, PFN_PHYS(pfn));
    pr_info("  Present:%d  Write:%d  User:%d  Dirty:%d\n",
            pte_present(*pte), pte_write(*pte),
            pte_user(*pte), pte_dirty(*pte));
    pte_unmap(pte);
}

static int __init pte_walk_init(void) {
    // 遍历当前进程的几个地址验证
    pr_info("=== Walking <module_init> (kernel text) ===\n");
    dump_pte((unsigned long)pte_walk_init);

    // 通过 /proc/PID/maps 找一个用户态地址传入
    return 0;
}

module_init(pte_walk_init);
MODULE_LICENSE("GPL");

实验 8: 对比 /dev/zero mmap vs MAP_ANONYMOUS 的效率差异

目的：验证两种"分配零填充内存"方式的性能差异。

// test_mmap_zero_vs_anon.c
#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <sys/mman.h>
#include <time.h>
#include <unistd.h>

#define SIZE (128 * 1024 * 1024UL)
static unsigned long long nstime(void) {
    struct timespec ts;
    clock_gettime(CLOCK_MONOTONIC, &ts);
    return ts.tv_sec * 1000000000ULL + ts.tv_nsec;
}

int main(void) {
    volatile char *p;
    unsigned long long t0, t1;
    int fd;

    // 方法1: MAP_ANONYMOUS
    t0 = nstime();
    p = mmap(NULL, SIZE, PROT_READ|PROT_WRITE,
             MAP_ANONYMOUS|MAP_PRIVATE, -1, 0);
    for (unsigned long i = 0; i < SIZE / 4096; i++)
        p[i * 4096] = 1;
    t1 = nstime();
    printf("MAP_ANONYMOUS: %llu ms\n", (t1 - t0) / 1000000);
    munmap((void *)p, SIZE);

    // 方法2: /dev/zero mmap
    fd = open("/dev/zero", O_RDONLY);
    t0 = nstime();
    p = mmap(NULL, SIZE, PROT_READ|PROT_WRITE,
             MAP_PRIVATE, fd, 0);
    for (unsigned long i = 0; i < SIZE / 4096; i++)
        p[i * 4096] = 1;
    t1 = nstime();
    printf("/dev/zero mmap:  %llu ms\n", (t1 - t0) / 1000000);
    munmap((void *)p, SIZE);
    close(fd);

    return 0;
}

预期结果：MAP_ANONYMOUS 略快于 /dev/zero，因为 MAP_ANONYMOUS 走 do_anonymous_page 而 /dev/zero 走文件缺页路径 do_fault（多一次 file_operations 解引用）。
