ARM64 early_fixmap_init() 深度分析

> 基于 Linux 6.18.1, ARM64, 4KB 页 / 48-bit VA / 4 级页表配置

---

1. 概述

early_fixmap_init() 在 setup_arch() 早期被调用，负责在 swapper_pg_dir 中建立 fixmap 区域的 页表骨架（PGD → PUD → PMD → PTE 的链路），但 不填入任何最终映射。后续通过 __set_fixmap() 按需将物理地址写入 PTE 条目。

setup_arch()
  └─ early_fixmap_init()        ← 建立骨架
  └─ early_ioremap_init()       ← 初始化 early_ioremap 基础设施
  └─ fixmap_remap_fdt()         ← 第一个使用者：映射 FDT
  └─ ...
  └─ paging_init()              ← 建立完整的 swapper_pg_dir

---

  │

注意：fixmap 的虚拟地址是 从高往低增长 的。__fix_to_virt(idx) = FIXADDR_TOP - ((idx) << PAGE_SHIFT)。

2.4 enum fixed_addresses 与 FIXADDR_TOP / FIXADDR_START 的关系

enum 值是 页序号（index） 而非地址。转换为虚拟地址的公式：

// include/asm-generic/fixmap.h:21
#define __fix_to_virt(x)  (FIXADDR_TOP - ((x) << PAGE_SHIFT))

enum 值每 +1，虚拟地址向下偏移 1 个 4KB 页面：

FIX_HOLE             = 0   →  __fix_to_virt(0) = FIXADDR_TOP - 0*4K      = FIXADDR_TOP
FIX_FDT_END          = 1   →  __fix_to_virt(1) = FIXADDR_TOP - 1*4K      = FIXADDR_TOP - 0x1000
FIX_EARLYCON_MEM_BASE      →  __fix_to_virt(2) = FIXADDR_TOP - 2*4K
FIX_TEXT_POKE0              →  __fix_to_virt(3) = FIXADDR_TOP - 3*4K
...
__end_of_permanent_fixed_addresses →  __fix_to_virt(此值) = FIXADDR_TOP - FIXADDR_SIZE
                                                                         = FIXADDR_START
...
__end_of_fixed_addresses          →  __fix_to_virt(此值) = FIXADDR_TOP - FIXADDR_TOT_SIZE
                                                                         = FIXADDR_TOT_START

需要 > 4KB 空间的条目，通过跳过多个 enum 值来「预留」多个页面：

// 设备树：需要 DIV_ROUND_UP(MAX_FDT_SIZE, PAGE_SIZE) + 1 个页面
FIX_FDT_END,                                          // idx = N
FIX_FDT = FIX_FDT_END + DIV_ROUND_UP(MAX_FDT_SIZE, PAGE_SIZE) + 1,  // idx = N + 页数

// KVM VNCR：每个 CPU 一个 4KB 槽
FIX_VNCR_END,
FIX_VNCR = FIX_VNCR_END + NR_CPUS,

// 临时 boot 映射：256KB × 7 个 slot = 448 个页面
FIX_BTMAP_BEGIN = FIX_BTMAP_END + TOTAL_FIX_BTMAPS - 1,  // 448 pages

FIXADDR_SIZE = __end_of_permanent_fixed_addresses << PAGE_SHIFT 的直观含义：

__end_of_permanent_fixed_addresses 的值 ≈ 永久 fixmap 区域占用的 enum 槽位数。左移 PAGE_SHIFT (12) 后就是占用的总字节数：槽位数 × 4KB。

FIXADDR_TOP │ │ FIX_HOLE (idx 0) ← __fix_to_virt(0) │ FIX_FDT_END (idx 1) │ ...FIX_FDT... (idx N) ← max_fdt 窗口 │ FIX_EARLYCON_MEM_BASE │ FIX_TEXT_POKE0 │ FIX_VNCR (KVM 可选) │ FIX_ENTRY_TRAMP_TEXT* (KPTI 可选) │ ├── __end_of_permanent_fixed_addresses ← 永久区域底部 │ __fix_to_virt(此值) = FIXADDR_START │ │ FIX_BTMAP_BEGIN ... FIX_BTMAP_END ← early_ioremap 临时映射 │ FIX_PTE, PMD, PUD, P4D, PGD ← 页表创建窗口 │ └── __end_of_fixed_addresses ← 全部 fixmap 底部 __fix_to_virt(此值) = FIXADDR_TOT_START

注意： 源码中 fixmap.h:103 有一个小 bug —— #define FIXADDR_START (FIXADDR_TOP - FIXADDR_SIZE) 缺了宏名 FIXADDR_START，但因为 arm64 代码中无引用，不影响编译。

4. 执行前状态

early_fixmap_init() 在 setup_arch() 中调用时：

  • swapper_pg_dir 已通过 memcpy 从 init_pg_dir 拷入根 PGD 条目
  • PGD 中 只有内核映像的条目（PGD index ≈ 256）
  • fixmap 区域的 PGD[511] 为空
  • bm_pud/bm_pmd/bm_pte 全在 BSS 段，初始全零
  • linear map 尚未建立（paging_init 还没跑）
  • 只能用 __pa_symbol() (基于 kimage_voffset) 做地址转换，不能用 virt_to_phys() (依赖 linear map)

---

5. 执行过程（4 步建立骨架）

5.1 入口：early_fixmap_init()

void __init early_fixmap_init(void)
{
    unsigned long addr = FIXADDR_TOT_START;
    unsigned long end = FIXADDR_TOP;

    pgd_t *pgdp = pgd_offset_k(addr);        // → &swapper_pg_dir[511]
    p4d_t *p4dp = p4d_offset_kimg(pgdp, addr); // 4级: P4D 折叠, p4dp == pgdp
    early_fixmap_init_pud(p4dp, addr, end);
}
  • pgd_offset_k(addr) = init_mm.pgd + pgd_index(addr) = &swapper_pg_dir[511]
  • 4 级页表下 P4D 被折叠：p4d_offset_kimg 直接返回 pgdp 本身（强转类型）

5.2 第 1 步：填充 PGD[511] → bm_pud

// early_fixmap_init_pud()
p4d = READ_ONCE(*p4dp);           // 读 swapper_pg_dir[511], 为 0 (空)
if (p4d_none(p4d))
    __p4d_populate(p4dp, __pa_symbol(bm_pud), P4D_TYPE_TABLE | P4D_TABLE_AF);

写入：

swapper_pg_dir[511] = PA(bm_pud) | 0x3    ← TABLE descriptor + AF bit

5.3 第 2 步：填充 bm_pud[511] → bm_pmd

// early_fixmap_init_pmd()
pudp = pud_offset_kimg(p4dp, addr);  // → &bm_pud[511]
pud = READ_ONCE(*pudp);              // 为 0 (空)
if (pud_none(pud))
    __pud_populate(pudp, __pa_symbol(bm_pmd), PUD_TYPE_TABLE | PUD_TABLE_AF);

写入：

bm_pud[511] = PA(bm_pmd) | 0x3    ← TABLE descriptor + AF bit

5.4 第 3 步：循环填充 bm_pmd[idx] → bm_pte[i]

pmdp = pmd_offset_kimg(pudp, addr);   // → &bm_pmd[pmd_index(FIXADDR_TOT_START)]
do {
    next = pmd_addr_end(addr, end);
    early_fixmap_init_pte(pmdp, addr); // 对每个 PMD 条目填 PTE
} while (pmdp++, addr = next, addr != end);

循环 3 次（NR_BM_PTE_TABLES = 3），每次：

// early_fixmap_init_pte()
pmd = READ_ONCE(*pmdp);            // 为 0
if (pmd_none(pmd)) {
    ptep = bm_pte[BM_PTE_TABLE_IDX(addr)];
    __pmd_populate(pmdp, __pa_symbol(ptep), PMD_TYPE_TABLE | PMD_TABLE_AF);
}

写入（3 次循环）：

bm_pmd[idx+0] = PA(bm_pte[0]) | 0x3
bm_pmd[idx+1] = PA(bm_pte[1]) | 0x3
bm_pmd[idx+2] = PA(bm_pte[2]) | 0x3

5.5 第 4 步：PTE 层 —— 不填充

所有 bm_pte[][] 保持为 0。只建骨架，具体物理映射留给 __set_fixmap() 按需填入。

7. 地址转换：为什么用 _kimg 而非 _virt

7.1 问题

early_fixmap_init() 运行时 linear map 还没建立（paging_init() 还没跑），所以不能用 virt_to_phys()（它依赖 linear map 的 PAGE_OFFSET - PHYS_OFFSET 偏移）。

7.2 两套地址转换

接口公式适用时机
__pa_symbol(x) / __kimg_to_phys(x)VA - kimage_voffset内核映像内符号，任何时候可用
virt_to_phys(x) / __virt_to_phys(x)VA - PAGE_OFFSET + PHYS_OFFSETlinear map 地址，paging_init 后可用

7.3 kimage_voffset 的赋值

在 head.S 的 __primary_switched（第 233-235 行）中赋值：

adrp    x4, _text          // x4 = _text 的运行时物理地址 (通过 PC-relative)
sub     x4, x4, x0         // x4 = _text_PA - _text_VA（实际是负值）
                            // 注: x0 此时 = __pa(_text)，但上面已经是 PA
str_l   x4, kimage_voffset  // 存入全局变量

实际关系：kimage_voffset = VA(kernel) - PA(kernel)，所以 PA = VA - kimage_voffset。

7.4 代码中的体现

注释（fixmap.c:103-107）明确指出：

/*
 * The p*d_populate functions call virt_to_phys implicitly so they can't be used
 * directly on kernel symbols (bm_p*d). This function is called too early to use
 * lm_alias so __p*d_populate functions must be used to populate with the
 * physical address from __pa_symbol.
 */

因此代码中：

  • 取 PGD/PUD/PMD 指针用 *_offset_kimg()（通过 __phys_to_kimg 转换）
  • 填充描述符用 __p*d_populate() + __pa_symbol()（直接写物理地址）
  • 不用 普通的 p*d_populate()（内部调用 virt_to_phys，此时会出错）

7.5 pgdp / p4dp 的地址性质

early_fixmap_init() 中的 pgdp、p4dp、pudp、pmdp 指针都是 虚拟地址（在内核映像映射 kimg 空间中），不是物理地址。CPU 可以直接解引用它们，因为此时内核映像的映射已经建好了（由 init_pg_dir → swapper_pg_dir 传递）。

8. 16K 页的特殊处理

if (CONFIG_PGTABLE_LEVELS > 3 && !p4d_none(p4d) &&
    p4d_page_paddr(p4d) != __pa_symbol(bm_pud)) {
    BUG_ON(!IS_ENABLED(CONFIG_ARM64_16K_PAGES));
}

在 16KB 页 + 4 级页表配置下，内核映像和 fixmap 可能共享同一个顶层 PGD 条目。此时 PGD[idx] 已经被 kernel mapping 填充，指向一个由 map_kernel 创建的 PUD 表（不是 bm_pud）。代码允许这种情况但加了 BUG_ON 确保只在 16K 页模式下发生。

4KB 页 / 48-bit VA 下此分支不会触发，因为 kernel image（PGD ≈ 256）和 fixmap（PGD = 511）使用不同的 PGD 条目。

9. __set_fixmap()：填充 PTE

骨架建好后，通过 __set_fixmap() 映射具体物理页：

void __set_fixmap(enum fixed_addresses idx, phys_addr_t phys, pgprot_t flags)
{
    unsigned long addr = __fix_to_virt(idx);   // idx → 虚拟地址
    pte_t *ptep = fixmap_pte(addr);            // 直接用 C 数组索引取 PTE 指针

    if (pgprot_val(flags))
        __set_pte(ptep, pfn_pte(phys >> PAGE_SHIFT, flags));  // 映射
    else {
        __pte_clear(&init_mm, addr, ptep);                     // 取消映射
        flush_tlb_kernel_range(addr, addr + PAGE_SIZE);
    }
}

fixmap_pte() 直接用 C 数组索引，不走页表遍历：

static inline pte_t *fixmap_pte(unsigned long addr)
{
    return &bm_pte[BM_PTE_TABLE_IDX(addr)][pte_index(addr)];
}

这是因为 bm_pte 数组既是页表本身（MMU 硬件通过物理地址访问），又是内核可直接寻址的 BSS 变量（CPU 通过虚拟地址访问）。两者指向同一块物理内存。

9.1 FIX_PTE/PMD/PUD/P4D/PGD：五级临时窗口

fixmap 末尾的这 5 个槽各自对应一级页表的 单页临时映射窗口，用于把某个页表页映射到 fixmap 空间从而读写它的条目：

// pgtable.h 中的定义
#define pgd_set_fixmap(addr)   ((pgd_t *)set_fixmap_offset(FIX_PGD, addr))
#define pte_set_fixmap(addr)   ((pte_t *)set_fixmap_offset(FIX_PTE, addr))
#define pmd_set_fixmap(addr)   ((pmd_t *)set_fixmap_offset(FIX_PMD, addr))

// pud_set_fixmap / p4d_set_fixmap 同理
槽名映射的物理页典型场景
FIX_PTE某个 PTE 表页（叶子，512 个 PTE 条目）分配新 PTE 页后填充映射
FIX_PMD某个 PMD 表页（512 个 PMD 条目）分配新 PMD 页后连接 PUD→PMD
FIX_PUD某个 PUD 表页（512 个 PUD 条目）分配新 PUD 页后连接 P4D→PUD
FIX_P4D某个 P4D 表页（512 个 P4D 条目）分配新 P4D 页后连接 PGD→P4D
FIX_PGDswapper_pg_dir 本身运行时修改只读的 PGD 条目

核心矛盾：你要修改的页表页本身也是一个物理页，需要虚拟地址才能访问。 当 linear map 覆盖不到，或者内核映像已变成只读时，fixmap 就是唯一途径。

9.2 五级都要的原因：层层分配

以 vmalloc 创建 PGD → PTE 的完整路径为例，每一步都可能需要分配一个新的页表页：

alloc_init_p4d(pgdp, addr, ...)
  │
  │  PGD 条目为空？
  ├─ YES → 分配 P4D 表页 → p4d_set_fixmap(p4d_phys)    // FIX_P4D 临时映射 P4D 页
  │                          __pgd_populate(pgdp, ...)   // set_swapper_pgd → FIX_PGD 窗口
  │
  └─ alloc_init_pud(p4dp, addr, ...)
       │  P4D 条目为空？
       ├─ YES → 分配 PUD 表页 → pud_set_fixmap(pud_phys)  // FIX_PUD 临时映射 PUD 页
       │
       └─ alloc_init_pmd(pudp, addr, ...)
            │  PUD 条目为空？
            ├─ YES → 分配 PMD 表页 → pmd_set_fixmap(pmd_phys) // FIX_PMD
            │
            └─ alloc_init_pte(pmdp, addr, ...)
                 │  PMD 条目为空？
                 └─ YES → 分配 PTE 表页 → pte_set_fixmap(pte_phys)  // FIX_PTE
                                              init_pte(ptep, addr, phys, prot)

FIX_PGD 和 FIX_P4D 都是临时映射页表页，只不过 FIX_PGD 映射的是 PGD 级表页（swapper_pg_dir），FIX_P4D 映射的是 P4D 级表页。

9.3 FIX_PGD 详解：生命周期与调用链

唯一使用点：set_swapper_pgd()（mmu.c:77）

void set_swapper_pgd(pgd_t *pgdp, pgd_t pgd)
{
    pgd_t *fixmap_pgdp;

    if (rodata_is_rw) {
        WRITE_ONCE(*pgdp, pgd);           // 早期：swapper_pg_dir 还处于可写状态
        return;
    }

    // 后期：swapper_pg_dir 已只读，必须通过 fixmap 后门
    spin_lock(&swapper_pgdir_lock);
    fixmap_pgdp = pgd_set_fixmap(__pa_symbol(pgdp));
    //            └─ set_fixmap_offset(FIX_PGD, PA(swapper_pg_dir))
    //                 └─ __set_fixmap(FIX_PGD, PA, 可写)
    //                      └─ bm_pte[2][idx] = PA | 可写属性   ← 填入 PTE
    WRITE_ONCE(*fixmap_pgdp, pgd);         // 通过 fixmap 窗口写 swapper_pg_dir
    pgd_clear_fixmap();                    // 用完立刻清除 PTE
    spin_unlock(&swapper_pgdir_lock);
}

FIX_PGD 的生命周期：

early_fixmap_init() mark_rodata_ro() vmalloc() → set_swapper_pgd() ═══════════════════ ═══════════════ ════════════════════════════════ bm_pte[FIX_PGD] = 0 bm_pte[FIX_PGD] = 0 pgd_set_fixmap() （骨架就绪，末级空） （仍然为空） → PTE = PA(swapper_pg_dir) | RW ↓ rodata_is_rw = TRUE rodata_is_rw = FALSE WRITE_ONCE → 写入 ↓ 直接写无保护 必须走后门 pgd_clear_fixmap() → PTE = 0 （归还）

调用 set_swapper_pgd 的场景：

这些调用链的最终触发源：vmalloc/vmap、KASAN 初始化、EFI 运行时映射——任何运行时需要往 swapper_pg_dir 插入新条目的操作。

9.4 rodata_is_rw 的分界

下面是 set_swapper_pgd() 的两个阶段：

阶段 1：paging_init() 之前（rodata_is_rw == TRUE）

  pgdp = &swapper_pg_dir[509];     // kimg 虚拟地址，对应内核映像内的位置
  WRITE_ONCE(*pgdp, new_pgd);      // 直接写——此时内核映像页权限为 RW


阶段 2：paging_init() → mark_rodata_ro() 之后（rodata_is_rw == FALSE）

  pgdp = &swapper_pg_dir[509];     // 同样的 kimg 虚拟地址
  WRITE_ONCE(*pgdp, new_pgd);      // ❌ PAGE FAULT——同一 VA 现在映射为 RO

  // swapper_pg_dir 这同一块物理内存现在有两个 VA 映射：
  //   映射 1（kimg）：只读  — 用于 CPU 读页表、MMU 走表
  //   映射 2（fixmap）：可写 — 用于 CPU 修改页表条目

  fixmap_pgdp = pgd_set_fixmap(__pa_symbol(pgdp));
  //            └─ 给 PA(swapper_pg_dir) 建立第 2 个映射，权限 RW
  WRITE_ONCE(*fixmap_pgdp, new_pgd);   // ✅ 走 fixmap 写同一块物理内存
PA(swapper_pg_dir) = 0x8145_F000（同一块 4KB 物理内存） │ ┌──────────────┴──────────────┐ │ │ 映射 1（kimg VA） 映射 2（fixmap VA） VA = kernel_image_base VA = __fix_to_virt(FIX_PGD) + offset(swapper_pg_dir) = FIXADDR_TOP - FIX_PGD*4K 权限：RO（！） 权限：RW │ │ ▼ ▼ CPU 可读，不可写 CPU 可读可写 MMU 走表用 set_swapper_pgd 专用

10. 第一个使用者：fixmap_remap_fdt()

void *__init fixmap_remap_fdt(phys_addr_t dt_phys, int *size, pgprot_t prot)
{
    const u64 dt_virt_base = __fix_to_virt(FIX_FDT);  // FDT 的 fixmap 虚拟地址

    // 1. 映射第一页，读取 FDT header
    create_mapping_noalloc(dt_phys_base, dt_virt_base, PAGE_SIZE, prot);
    // → 内部调用 __set_fixmap() 填充 bm_pte 中对应的 PTE

    // 2. 验证 FDT magic，获取 size
    *size = fdt_totalsize(dt_virt);

    // 3. 如果 FDT 跨页，映射剩余页
    create_mapping_noalloc(dt_phys_base, dt_virt_base, offset + *size, prot);

    return dt_virt;  // 返回 fixmap 空间中的虚拟地址
}

此时通过 fixmap 窗口（FIX_FDT_END ~ FIX_FDT）可以访问设备树，而不需要完整的 linear map。

11. 总结

要点说明
目的在 swapper_pg_dir 中建立 fixmap 区域的 4 级页表骨架
写入的描述符5 个 (1 PGD + 1 PUD + 3 PMD)，全是 TABLE 描述符
PTE 层全部保持为 0，由 __set_fixmap() 按需填充
页表存储PGD 在 linker script 分配区(.text 后)；PUD/PMD/PTE 在 BSS 段的静态数组
地址转换只用 __pa_symbol() + *_offset_kimg()，不用 virt_to_phys()
不用 virt_to_phys 的原因linear map 还没建立，只有 kimage_voffset 可用
调用时机setup_arch() 早期，在 paging_init() 之前
第一个使用者fixmap_remap_fdt() — 映射设备树
特殊情况16K 页下 kernel 和 fixmap 可能共享 PGD 条目
