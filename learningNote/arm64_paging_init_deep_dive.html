ARM64 paging_init 深度解析与内存映射总结

从 memblock 数据操作到内核页表建立的完整链路

1. paging_init 在启动流程中的位置

paging_init() 是 ARM64 启动早期承上启下的关键一环：它的上游是「memblock 已经就绪」，下游是「伙伴系统（buddy）即将接手物理内存」。它在 setup_arch() 中的调用位置如下（arch/arm64/kernel/setup.c）：

arm64_memblock_init();   // ① 解析 FDT/EFI，建立 memblock（知道系统有哪些内存 bank）

paging_init();           // ② 建立线性映射 + 身份映射（本文主角）

acpi_table_upgrade();
acpi_boot_table_init();
...
bootmem_init();          // ③ 初始化 buddy 分配器（释放 memblock 中的空闲内存给伙伴系统）
kasan_init();

为什么这个顺序是必然的？

  • arm64_memblock_init() 之前：内核还不知道「系统物理内存的完整布局」，只有 bootloader 传来的 FDT，无法映射全部内存。
  • bootmem_init() 要建立 zone、free page，必须能通过线性映射访问到每一页物理内存 —— 这正是 paging_init() 干的事。
  • 所以 paging_init() 正好卡在「memblock 就绪」与「buddy 接手」之间。
一句话定位：paging_init() 在 memblock 建立之后、buddy 分配器启动之前，把「所有物理内存」映射进内核页表，使内核后续能自由访问全部 RAM。

2. 前置知识回顾：memblock 三件套

理解 paging_init 之前，需要先回顾本系列前面讨论过的三个 memblock 核心机制。

2.1 memblock 数据结构与 regions 数组

memblock 是启动早期的物理内存分配器。系统有 memblock.memory（可用内存）和 memblock.reserved（保留内存）两类，每类都用一个 按地址升序、不重叠 的 region 数组表示：

struct memblock_region {
    phys_addr_t base;   // 起始物理地址
    phys_addr_t size;   // 大小
    enum memblock_flags flags;  // 如 MEMBLOCK_NOMAP / MEMBLOCK_HOTPLUG
    int nid;            // NUMA node
};

// 例：memblock.memory 的 regions 数组
idx 0: [0x0000_0000, 0x2000_0000)   // 0~512MB
idx 1: [0x2000_0000, 0x4000_0000)   // 512MB~1GB
idx 2: [0x4000_0000, 0x6000_0000)   // 1GB~1.5GB

2.2 memblock_isolate_range 输出参数

函数签名：

static int memblock_isolate_range(struct memblock_type *type,
                                  phys_addr_t base, phys_addr_t size,
                                  int *start_rgn, int *end_rgn)

它把范围 [base, base+size) 从 region 数组中「隔离」出来——任何跨界的 region 都会在边界处被劈开。完成后，范围内的 region 恰好是一段连续下标区间 [start_rgn, end_rgn)。

  • *start_rgn：范围内第一个 region 的下标（含）
  • *end_rgn：范围内最后一个 region 的下一个下标（不含，past-the-end）

这两个是输出参数（不是回调）：C 函数只能 return 一个值，额外结果通过指针传回。调用方拿到下标区间后，就能精确批量操作这段 region。

2.3 memblock_merge_regions 合并相邻 region

static void memblock_merge_regions(struct memblock_type *type,
                                   unsigned long start_rgn,
                                   unsigned long end_rgn)

它是 isolate 的「逆操作」：把物理相邻、NUMA node 相同、flags 完全相同的相邻 region 合并成一块，恢复数组的紧凑。典型使用是 memblock_setclr_flag 的「isolate → 改 flags → merge」三步曲——isolate 劈出的碎片在 flags 改完后属性一致，需要再并回去。

这一组「isolate / merge」机制是 memblock 大多数范围操作的公共底座，map_mem 里的 memblock_mark_nomap、for_each_mem_range 都建立在其上。

3. paging_init 源码与调用时机

完整源码（arch/arm64/mm/mmu.c:1351）非常简短，只有四个调用：

void __init paging_init(void)
{
    map_mem(swapper_pg_dir);   // ① 建立线性映射（映射所有物理内存）

    memblock_allow_resize();   // ② 允许 memblock 动态扩容

    create_idmap();            // ③ 建立身份映射（idmap）

    declare_kernel_vmas();     // ④ 注册内核各段的早期 VM 区
}

虽然只有四行，但每一行都承载了启动早期内存管理的核心任务。下面逐一展开。

4. 步骤一：map_mem 建立线性映射

4.1 线性映射的定义

线性映射（linear map / direct map）是内核访问所有物理内存的固定映射，满足 virt = phys + PAGE_OFFSET（即 __phys_to_virt()）。map_mem 的核心循环：

for_each_mem_range(i, &start, &end) {          // 遍历 memblock.memory 每个 bank
    __map_memblock(pgdp, start, end, pgprot_tagged(PAGE_KERNEL), flags);
}

// __map_memblock 是薄封装：
__create_pgd_mapping(pgdp, start, __phys_to_virt(start), end - start,
                     prot, early_pgtable_alloc, flags);

关键属性决策：

属性含义
NO_EXEC_MAPPINGS线性映射默认不可执行（PXN），内核 W^X 保护的一部分
pgprot_tagged(PAGE_KERNEL)用 MT_NORMAL_TAGGED 属性，支持 MTE 读写 allocation tags
NO_BLOCK_MAPPINGS / NO_CONT_MAPPINGSforce_pte_mapping() 时（rodata_full / KFENCE / Realm）退化为 4KB 页级映射，便于细粒度改权限
实测佐证：在本机 serial.logs（QEMU 1GB 内存）里，map_mem 建线性映射时 early_pgtable_alloc() 被调用了 413 次，每次分配 4KB 页表页，共 413 × 4KB ≈ 1.65MB，地址从 0x7ffa5000 向下（top-down）铺到 0x7fe08000，全部打上 MEMBLOCK_RSRV_KERN (0x20) 标志。详见 附录。

4.2 两步映射内核镜像的技巧

map_mem 最精巧的设计是两步映射内核镜像，避免给只读的 text/rodata 制造「可写 + 可执行」的危险别名：

// 第 0 步：先把内核镜像 [_text, __init_begin) 临时标记 NOMAP
memblock_mark_nomap(kernel_start, kernel_end - kernel_start);

// 第 1 步：循环映射所有内存 bank（for_each_mem_range 会自动跳过 NOMAP 的内核镜像）
for_each_mem_range(i, &start, &end)
    __map_memblock(pgdp, start, end, pgprot_tagged(PAGE_KERNEL), flags);

// 第 2 步：单独映射内核镜像的线性别名（可写但不可执行，且后续可改 RO）
__map_memblock(pgdp, kernel_start, kernel_end, PAGE_KERNEL, NO_CONT_MAPPINGS);
memblock_clear_nomap(kernel_start, kernel_end - kernel_start);
经过这一步，内核镜像有了两个虚拟映射：① 早期 map_kernel 建的链接地址映射（ROX 等）；② 这里的线性别名映射（暂时可写）。后者随后由 mark_linear_text_alias_ro() 改成只读。

5. 步骤二：memblock_allow_resize

源码（mm/memblock.c:2106）：

void __init memblock_allow_resize(void)
{
    memblock_can_resize = 1;
}

作用只有一个：置位 memblock_can_resize，允许 memblock 的 region 数组在容量不足时动态扩容（调用 memblock_double_array 翻倍）。

  • 早期阶段，region 数组用的是静态预留的容量（INIT_MEMBLOCK_REGIONS / INIT_MEMBLOCK_RESERVED_REGIONS），扩容被禁止。
  • 现在线性映射已建好，内核可以安全地 memblock_alloc 更大数组来扩容，所以放开限制。
  • 这也是为什么 paging_init 把 map_mem 放在 memblock_allow_resize 之前：扩容需要用到线性映射才能访问新分配的页表内存。

6. 步骤三：create_idmap 建立身份映射

源码（arch/arm64/mm/mmu.c:1324）：

static void __init create_idmap(void)
{
    phys_addr_t start = __pa_symbol(__idmap_text_start);
    phys_addr_t end   = __pa_symbol(__idmap_text_end);
    phys_addr_t ptep  = __pa_symbol(idmap_ptes);

    __pi_map_range(&ptep, start, end, start, PAGE_KERNEL_ROX,
                   IDMAP_ROOT_LEVEL, (pte_t *)idmap_pg_dir, false,
                   __phys_to_virt(ptep) - ptep);
    ...
}

身份映射（identity map）把 __idmap_text 段映射为 virt == phys，放进 idmap_pg_dir。它的用途是：

  • 在「关 MMU / 切 TTBR」的瞬间，CPU 还能继续执行（因为 idmap 下物理地址 == 虚拟地址，即使 MMU 状态变化也不会跑飞）。
  • CPU 热插拔、休眠唤醒、KPTI 切换等场景都需要在 idmap 里执行临界代码。
与早期 idmap 的区别：head.S 阶段已有 __pi_init_idmap_pg_dir 的临时 idmap；这里的 create_idmap() 是建立正式的、长期使用的 idmap_pg_dir，供内核后续运行期使用。

7. 步骤四：declare_kernel_vmas 注册内核段

源码（arch/arm64/mm/mmu.c:1306）：

static void __init declare_kernel_vmas(void)
{
    static struct vm_struct vmlinux_seg[KERNEL_SEGMENT_COUNT];

    declare_vma(&vmlinux_seg[0], _text, _etext, VM_NO_GUARD);
    declare_vma(&vmlinux_seg[1], __start_rodata, __inittext_begin, VM_NO_GUARD);
    declare_vma(&vmlinux_seg[2], __inittext_begin, __inittext_end, VM_NO_GUARD);
    declare_vma(&vmlinux_seg[3], __initdata_begin, __initdata_end, VM_NO_GUARD);
    declare_vma(&vmlinux_seg[4], _data, _end, 0);
}

它把内核镜像的 5 个逻辑段（text / rodata / inittext / initdata / data）分别注册成早期 VM 区（early vmap area），通过 vm_area_add_early() 挂到 vmlist。

这些 VMA 不参与实际映射（映射已在 map_mem/早期 map_kernel 完成），而是为运行期查询服务，典型用途：

  • is_vmalloc_addr()：判断某虚拟地址是否属于内核映像/vmalloc 区。
  • /proc/kcore、内核 core dump：需要知道内核各段的地址范围与物理地址。
  • 后续 vmap_area 体系接管前的过渡登记。

8. 两次映射的本质区别

回到最初的问题：head.S 里 bl __pi_early_map_kernel 不是已经映射了一次吗？为什么 map_mem(swapper_pg_dir) 还要再映射一次？

早期 __pi_early_map_kernel

  • 映射对象：只映射内核镜像 [_text, _end)
  • 页表：建在临时 init_pg_dir，随后拷根表并切到 swapper_pg_dir
  • 虚拟地址：链接地址 KIMAGE_VADDR + kaslr_offset
  • 目的：开 MMU、把内核搬到高半区虚拟地址跑
  • 约束：位置无关、无动态分配、只用 2MB block、静态页表

paging_init → map_mem

  • 映射对象：所有物理内存 bank（线性映射）
  • 页表：直接写入最终 swapper_pg_dir
  • 虚拟地址：phys + PAGE_OFFSET
  • 目的：内核以后访问/管理全部 RAM
  • 约束：memblock 就绪，可用 early_pgtable_alloc 动态分配页表

两者不是「二选一」，而是「补全」。看 map_kernel() 的结尾（pi/map_kernel.c:135）：

/* Copy the root page table to its final location */
memcpy((void *)swapper_pg_dir + va_offset, init_pg_dir, PAGE_SIZE);
idmap_cpu_replace_ttbr1((phys_addr_t)swapper_pg_dir);  // TTBR1 切到 swapper_pg_dir

这里其实有两次 TTBR1 切换：map_kernel() 先把映射建进 init_pg_dir，line 99 第一次切到 init_pg_dir 让内核镜像映射生效；然后 line 136 把根 PGD 那一页拷到 swapper_pg_dir（低层 PUD/PMD/PTE 仍原地不动，swapper_pg_dir 的 PGD 项指向它们），line 138 第二次切到 swapper_pg_dir。所以 early_map_kernel 返回时，活动页表已经是 swapper_pg_dir，而非 init_pg_dir。

修正后的共识：早期 map_kernel 与 map_mem 最终都收敛到 swapper_pg_dir。区别只在「怎么进去」：早期是「建在 init_pg_dir → 拷根表 → 切过来」，map_mem 是「直接往 swapper_pg_dir 里写」。因此二者不是两个页表，而是同一个页表的两批映射。
为什么不能一开始就 map_mem？因为早期阶段（1）memblock 还没建立，不知道系统有哪些内存 bank；（2）必须零依赖、无动态分配，只能用静态页表和 2MB block 映射；（3）NUMA node、NOMAP、MTE 等属性决策都要等 setup_arch 之后才有。

8.1 两个映射的精确时间点与代码位置

把「两个虚拟映射」落到具体的代码位置和时间点，共三条线、三个不同时刻：

#映射 / 改动代码位置调用链时机（真实日志）
①链接地址映射（text 天生 ROX）pi/map_kernel.c:87__primary_switch → __pi_early_map_kernel → early_map_kernel() → map_kernel()head.S 开 MMU 时
②线性别名映射（暂时可写）mmu.c:1132-1133start_kernel → setup_arch → paging_init → map_mem早期 C 启动（~0.000s）
③线性别名改只读mmu.c:980kernel_init → smp_init → smp_cpus_done → mark_linear_text_alias_roSMP 就绪后（~0.112s）

① 链接地址映射：text 一开始就是 ROX

入口在 head.S:518 的 bl __pi_early_map_kernel，进入 early_map_kernel() 再到 map_kernel()：

pgprot_t text_prot = PAGE_KERNEL_ROX;      // text 一开始就是 ROX
...
map_segment(init_pg_dir, &pgdp, va_offset, _stext, _etext, prot, ...);  // text 段
...
memcpy((void *)swapper_pg_dir + va_offset, init_pg_dir, PAGE_SIZE);
idmap_cpu_replace_ttbr1((phys_addr_t)swapper_pg_dir);   // 切 TTBR1

这份是内核镜像的链接地址映射（KIMAGE_VADDR + kaslr_offset），text 段用 PAGE_KERNEL_ROX（只读+可执行），是内核正式执行代码所依赖的映射。

② 线性别名映射：可写，且带 NO_CONT_MAPPINGS

// mmu.c:1132-1133，在 map_mem() 的第二步
__map_memblock(pgdp, kernel_start, kernel_end, PAGE_KERNEL, NO_CONT_MAPPINGS);  // 可写
memblock_clear_nomap(kernel_start, kernel_end - kernel_start);

kernel_start/kernel_end = [_text, __init_begin)，映射到线性别名 phys + PAGE_OFFSET，属性 PAGE_KERNEL（可写）。注释明确说「remove the write permission in mark_linear_text_alias_ro() below」，说明这份是给 hibernate 等子系统临时写访问用的。

③ 线性别名改只读：smp_cpus_done 里

// mmu.c:980
void __init mark_linear_text_alias_ro(void)
{
    update_mapping_prot(__pa_symbol(_text), (unsigned long)lm_alias(_text),
                        (unsigned long)__init_begin - (unsigned long)_text,
                        PAGE_KERNEL_RO);   // 把线性别名改成只读
}

注意它操作的是 lm_alias(_text)（linear map alias），不是 _text 本身——改的是线性别名这份，不动链接地址那份。调用链比预想晚很多：

// kernel/smp.c:1009 —— smp_init() 末尾
void __init smp_init(void) {
    bringup_nonboot_cpus(setup_max_cpus);   // 拉起次核
    ...
    smp_cpus_done(setup_max_cpus);          // → arch 的 smp_cpus_done
}
// arch/arm64/kernel/smp.c:438
void __init smp_cpus_done(unsigned int max_cpus) {
    ...
    mark_linear_text_alias_ro();            // smp.c:444
}

smp_cpus_done 由 kernel_init_freeable()（init/main.c:1585）里的 smp_init() 触发，属于内核 init 线程（PID 1）阶段——比 paging_init 晚得多。

真实日志时间戳（serial.logs）：

[0.112370] SMP: Total of 4 processors activated.   ← smp_cpus_done 打的（smp.c:440）
                                                   ← mark_linear_text_alias_ro 紧跟其后 ≈ 0.112s
别混淆第四步 mark_rodata_ro()：它和 mark_linear_text_alias_ro() 是两码事。mark_rodata_ro()（mmu.c:1138）改的是主映射里的 rodata（__start_rodata..__init_begin 从 RW 变 RO），调用链是 kernel_init() → mark_readonly()（init/main.c:1457）→ mark_rodata_ro()，发生在 free_initmem() 之后，对应日志 Freeing unused kernel memory: 13056K（[1.899136]），约 1.9 秒。

时序总结

head.S (开MMU)                → ① 链接地址映射: text 已是 ROX                       (~0.000s)
start_kernel → paging_init    → ② 线性别名映射: [_text,__init_begin) 可写            (~0.000s)
kernel_init → smp_cpus_done   → ③ 线性别名改只读 (mark_linear_text_alias_ro)        (~0.112s)
kernel_init → mark_readonly   → ④ 主映射 rodata 改只读 (mark_rodata_ro)             (~1.9s)

所以「线性别名暂时可写」这个窗口持续了约 0.1 秒（从 map_mem 到 smp_cpus_done），这期间 hibernate 等子系统可以写它，之后永久只读。

9. 完整启动时间线与页表切换

head.S: __primary_switch └─ __enable_mmu (临时空表 + 初始 idmap，先开 MMU) └─ __pi_early_map_kernel (映射内核镜像 → init_pg_dir) └─ map_kernel() ├─ 映射 _text.._end 各段到链接 VA ├─ idmap_cpu_replace_ttbr1(init_pg_dir) TTBR1 → init_pg_dir ├─ (CONFIG_RELOCATABLE) relocate_kernel() └─ memcpy swapper_pg_dir ← init_pg_dir 的 PGD 页 idmap_cpu_replace_ttbr1(swapper_pg_dir) TTBR1 → swapper_pg_dir └─ __primary_switched └─ start_kernel() └─ setup_arch() ├─ arm64_memblock_init() (解析 FDT，memblock 就绪) ├─ paging_init() ★本文主角 │ ├─ map_mem(swapper_pg_dir) 补全线性映射 │ ├─ memblock_allow_resize() 允许动态扩容 │ ├─ create_idmap() 正式 idmap │ └─ declare_kernel_vmas() 注册内核段 VMA ├─ bootmem_init() (buddy 接手内存) └─ kasan_init()

可以看到页表「接力」的关键节点：init_pg_dir（临时）→ swapper_pg_dir（最终），而 paging_init 负责在 swapper_pg_dir 里把「线性映射」这块拼图补全。

10. 总结表

函数 / 机制作用页表 / 数据结构
__pi_early_map_kernel早期映射内核镜像、开 MMU、搬内核init_pg_dir（临时）
memblock_isolate_range隔离范围，返回 region 下标区间 [start_rgn, end_rgn)memblock.regions[]
memblock_merge_regions合并相邻且属性相同的 regionmemblock.regions[]

核心结论

  1. memblock 是启动早期的内存账本，isolate / merge 是它所有范围操作的公共底座。
  2. paging_init 是页表「交接」的枢纽：它把 memblock 记录的物理内存变成内核能直接访问的线性映射。
  3. 两次映射各司其职：早期映射内核镜像自己（bootstrap），map_mem 映射全部内存（正式），两者在 swapper_pg_dir 里合流。
  4. 顺序即约束：memblock 就绪 → 线性映射 → 允许扩容 → 身份映射 → buddy 接手，每一步都依赖前一步的成果。

11.2 真实的 memblock 布局

日志里的 MEMBLOCK configuration 段落（对应前文第 2 节的 region 数组）：

MEMBLOCK configuration:
 memory size = 0x0000000040000000  reserved size = 0x00000000056398fb
 memory.cnt  = 0x1
 memory[0x0] [0x0000000040000000-0x000000007fffffff], 0x40000000 bytes on node 0 flags: 0x0
 reserved.cnt = 0xa

与「多 bank」的通用场景不同，这台机器只有 1 个 memory region（memory.cnt = 1），却有 10 个 reserved region（reserved.cnt = 0xa）。这正是前文讲的：memblock 用「按地址升序、不重叠」的 region 数组描述内存，isolate / merge 保证这个数组始终紧凑有序。

10 个 reserved region 逐一拆解：

region地址范围大小flags实际含义

reserved[1]0x48000000-0x480fffff1MB0x01MB 保留区（日志未标注，通常为 initrd/DTB）
reserved[2]0x7cc00000-0x7ebfffff32MB0x20CMA（cma: Reserved 32 MiB at 0x7cc00000）
reserved[3]0x7ec00000-0x7fbfffff16MB0x20struct page 数组（memmap_alloc，262144 页 × 64B = 16MB）

11.3 线性映射页表分配（map_mem 的产物）

前文第 4 节提到 map_mem 通过 early_pgtable_alloc() 动态分配页表。日志里能精确数出来：

// 每次分配一页（4KB），early_pgtable_alloc 调用 __memblock_reserve 把页表页保留下来
memblock_phys_alloc_range: 4096 bytes align=0x1000 ... early_pgtable_alloc+0x20/0x3c
__memblock_reserve: [0x7ffa5000-0x7ffa5fff] nid=-1 flags=20 ...   // 第 1 次
__memblock_reserve: [0x7ffa4000-0x7ffa4fff] nid=-1 flags=20 ...   // 第 2 次
... （自高地址向下逐个分配）...
__memblock_reserve: [0x7fe08000-0x7fe08fff] nid=-1 flags=20 ...   // 第 413 次
  • 413 次分配，每次 4096 字节 → 共 413 × 4KB = 1,691,648 B ≈ 1.65MB 页表页。
  • 地址自高向下（top-down）：从 0x7ffa5000 一路铺到 0x7fe08000，恰好落在内存顶部的 reserved[9] 区间内。
  • 验证：0x7ffa5000 - 0x7fe08000 = 0x19D000 = 1,691,648 = 413 × 4096，严丝合缝。
  • 这就是给 1GB RAM 建线性映射所需的页表总量 —— 也解释了为什么 paging_init 必须放在 memblock 就绪之后：这些页表页要靠 memblock_phys_alloc_range 来分配。
